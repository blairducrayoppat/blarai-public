### 2026-10-15 — An anchor list written by hand follows the evidence only until someone adds a citation

*Plain summary: the fourth review of the public-snapshot exclusion list passed it and left two small findings. Every file the public evidence documents point to is now itself protected from being held back, and the publisher refuses a repository whose protection files are missing instead of skipping the check without a word.*

The anchor list names the public evidence the posts cite, and the list of held-back paths may not exclude any of it. It was a hand list. The 35 anchored documents cite 44 more tracked paths (48 after main moved and the non-Markdown files under the anchors were read too) that no anchor covered (ADRs 042, 043, 045 and 049, the containment design overview, three dispositions, the mxc_1406 probe and its summary, the hook scripts, the tests the documents name), so a single broad line in the exclusion list would have removed a cited file with every control green. A lock now reads the anchored `.md` files from the index, takes every token (from every text file under the primary anchors, binaries and gzip skipped by sniffing, not only the Markdown ones) that equals a tracked file or a tracked directory of three or more segments, and fails for each one that no anchor covers and the allowlist `scripts/publicignore_cited_unanchored.txt` does not hold with a reason. All but one went into the anchor file below a `#:cited-only` line; the one allowlisted path is a coincidental match from vendored text. An anchored cited path is held by the existing anchored-but-excluded check, and a cited path nobody anchored is caught by the new lock. The publisher reads the same file and ignores comment lines, so both sides enforce the same entries.

Two choices were forced. The scan is one hop: anchoring the 44 made some of them documents that cite more, and scanning those in turn walks to the whole repository (CLAUDE.md alone names most of the tree), so the entries below the marker are anchored but not scanned, and that limit is written into the lock's docstring. Directories of one or two segments (`scripts/hooks`, `tests/security`) are areas, not citations: anchoring them would pin every file beneath. Rejected: allowlisting the 44. Each of them is public today, and an allowlist line would have documented a path as safe to remove that a post links.

The publisher side (agentic-setup, `fix/1785-publisher-anchor-phrase-files`) now refuses a repository whose source tree carries a `.publicignore` without `scripts/publicignore_anchors.txt` or without `scripts/publicignore_phrases.json`, naming the file. Its scratch test gained case 20 (each file missing alone, both missing, a tree with no list untouched) and a toggle that removes both refusals from a copy of the publisher and shows the tree with neither file then publishes; 66 checks pass. Older cases that built lists without the files were given them, and the case that expected a list matching every path to reach the empty-tree refusal now expects the anchor check to refuse first; a separate case removes the anchor check from a copy of the publisher to show the empty-tree refusal still fires.
