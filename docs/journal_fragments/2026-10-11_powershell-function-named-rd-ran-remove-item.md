### 2026-10-11 — A function named after an alias runs the alias: `Rd` deleted a tracked sentinel

*Plain summary: during the #1743 review a throwaway read-only scan script defined a PowerShell function called `Rd`; PowerShell resolves aliases before functions, and `rd` is an alias for `Remove-Item`, so every "read" call deleted something. It removed the tracked governed-core sentinel `.blarai-governed-core` from the main checkout for about ten minutes and stopped only because deleting a non-empty folder asks for confirmation.*

I did not write the script; a reviewer agent did, and reported it at once and restored the file from the HEAD blob (hash verified equal to HEAD's, `git status` clean afterwards). What I take from it: command resolution order in PowerShell is alias, then function, then cmdlet, so a helper named like any built-in alias (`rd`, `ls`, `cat`, `rm`, `cp`, `mv`, `del`, `dir`, `type`, `sort`, `sc`, `gc`) silently becomes the built-in. A read-only probe must use names with a verb-noun shape and a project prefix (`Get-ProbeAcl`), and must be run against a copy of the tree, never against the root of a shared checkout. The same incident ran a reviewer inside the main checkout while the standing gate was running on it, which the "serialize heavy loads" rule exists to avoid; the gate still finished green (13320 passed, 0 failed, 0 skipped) but a sentinel-dependent test could have failed for a reason unrelated to the code. An ignored root file that sorted before `.claude` may have been lost; it is git-ignored and unrecoverable from git, and nothing in the repository refers to it.
