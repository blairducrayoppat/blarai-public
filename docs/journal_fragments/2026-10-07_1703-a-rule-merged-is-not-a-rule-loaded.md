### 2026-10-07 — A rule that is merged is not a rule that is loaded

*Plain summary: A new session opened in a checkout that was behind main and quietly worked from the old rules; the session-start hook now says so out loud, and the review of that hook found its own tests were checking one path out of the three it claimed to guard.*

The morning's first #1699 session gated from an out-of-date CLAUDE.md because the primary checkout sat on a feature branch that had never merged the doctrine change (#1700) landed on main. Nothing was wrong with the rule; the rule was simply not in the room. #1703 closes that: at SessionStart the hook asks whether main's latest commit touching CLAUDE.md, `.claude/rules/`, `.claude/agents/` or `.claude/settings.json` is an ancestor of the checkout's HEAD, and if not it says which checkout, which branch and which commit is missing. It informs and never blocks, and a failure to decide is reported as a failure rather than read as "in sync".

I wrote five tests and a toggle proving the probe fails when the check is emptied, and thought that was a lock. The independent reviewer ran nine mutations against it. Dropping `.claude/rules` from the path list left all 75 tests green, and so did dropping `.claude/settings.json`: every fixture changed only CLAUDE.md. The merge-base error branch, the one that enforces "cannot decide is not in sync", could be turned into a fail-open with no test noticing. Both were mine to fix and were fixed in `281d3f33` (one fixture per path; an unborn HEAD that makes merge-base error). Smaller finds rode along: the failure text claimed rules were "not delivered for this tool call" at a moment with no tool call, a 10 s per-call git timeout inside a 15 s hook budget, and a scratch repo leaked into the temp directory on every run because git's object files are read-only on Windows.

The branch gate read 6 failed against a predicted 5. Five were environmental (three need the gitignored 14B model; two ADR-013 links resolve only from the home checkout, not from a worktree under BlarAI-worktrees) and the sixth was my own bug: renumbering the ROADMAP block with a counter that never incremented gave 21 rows rank 2. The prediction was wrong by exactly the one failure that was a defect, which is the reason the prediction is written first.

Trade-off: the check compares against the local `refs/heads/main`, so a clone with a stale main reads as in sync; all sixteen current trees are worktrees sharing refs, so I accepted the limit and wrote it into the docstring rather than adding a network fetch to a session-start hook. At review time eleven of those sixteen trees lag main's doctrine and none contains the hook, so it protects only checkouts that merge main after this lands.
