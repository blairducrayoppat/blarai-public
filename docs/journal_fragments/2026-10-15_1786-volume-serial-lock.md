### 2026-10-15 — A reviewer found the identifier the lock had no rule for

*Plain summary: the identity lock only knew two names, so a disk volume serial number (a stable machine identifier printed by `dir`) sat in two run records and the check read zero on it until a reviewer noticed. The lock and the scrub now cover volume serials: the machine's own, read live, and any "Volume Serial Number is" header from any machine.*

The round-2 review of the nono-9P control (#1755) found the raw `dir /x` header in both run JSONs; `--check` passed on them because the lock was built around the two names and had no concept of a third kind of identifier. The fix follows the host-name pattern with one difference forced by the value: a serial is 32 bits, so a pinned digest of it would be reversible in seconds and would amount to writing it down. The serials are therefore never pinned; they are read at run time from every local fixed volume (GetVolumeInformationW) and compared by digest in the dashed, bare-hex (either case) and decimal forms, in every byte view the name rules already use (JSON escapes, UTF-16, percent and ANSI, gzip). When no volume serial can be read the lock and `--check` fail rather than skip. The second rule needs no machine: the header text followed by a serial is a finding in any tracked file, which is what catches a serial copied in from another box. The scrub rewrites both to `XXXX-XXXX` and its log gives the file and the count, never the value.

Counts on main at 677f9344: zero files carry a live serial and zero carry the header, so `--check` reads 0 (the two run records are on the #1755 branch). Rejected: pinning the digest of this machine's serial for account-independence (it would publish the value); matching decimal only at ten digits (a serial below 2**32 prints shorter, and a collision costs one false report where a miss costs a leak). The same two rules run at the publishing edge: the Hugging Face preflight reads every file's content and name with `find_serial_hits` and refuses a live serial or a header (and refuses when no serial is readable); the community-export scrub rewrites both to the placeholder and its verifier's residual scan refuses either, each call site with a toggle test that fails the probe when the call is removed, and the two published qwen35_small directories and the NEP-0005 export still preflight clean. Not covered, and written into the honest limit: a serial from another machine that is not under the English header, a removable or unmounted volume, and the encodings the name rules already miss.
