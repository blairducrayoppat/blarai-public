### 2026-10-10 — A choice recorded only as a ticket comment was never compared against the alternative that is now the other project's preferred design

*Plain summary: the LA asked why coder containment uses a dedicated account and not AppContainer; the answer on disk is that no ADR ever compared them, so I wrote the comparison as an amendment to ADR-045 and sent the open question to a study.*

The LA saw that nolabs-ai's sandbox project, nono, proposes AppContainer as its preferred Windows mechanism with a dedicated user, restricted token and NTFS ACLs as the documented fallback, and asked whether we had ever written down why we chose the fallback shape. I searched the docs for AppContainer and restricted token before answering. ADR-045 does not mention AppContainer; its alternatives list covers leaving containment off, the egress gap, Bitdefender, a third-party sandbox, a process-kill fix, moving the whole dispatch and a guest-only coder. The choice itself is Decision 1(b) on #787, comment 1574, a ticket comment. The only side-by-side is one table in the 2026-07-09 research brief, assembled from web sources and not measured here: AppContainer rated high setup and severe toolchain damage, the restricted local user rated low on both.

Two things made the record thinner than it looked. The earlier AppContainer deferral, in the June capstone, was about the Assistant Orchestrator and rested on GPU and TPM access that the coder does not need when the model stays host-side, so it does not carry over, and nobody had checked that it did not. And the 2026-09-17 study's AppContainer probe failed on a working-directory error before it tested anything, so the only AppContainer measurement we own measured nothing. What we have never done is run the coder toolchain inside an AppContainer.

nono's proposal (NEP-0005, draft, 2026-09-29) was read from the raw file at commit `62bb720b` on 2026-10-10 under #1740, and it matches what the LA described. Its Phase 1 is the per-account WFP block we spiked in #1671, which makes our design that proposal's fallback plus its first phase. That is a statement about a draft, not evidence that AppContainer holds a coder on this machine, and the amendment says so.

The rejected path was to rewrite ADR-045's alternatives section in place. The ADR's own convention is an amendment with earlier text untouched, and rewriting would have hidden that the comparison arrived three months after the decision. The second rejected path was to answer the LA's question with a recommendation to switch; the record supports neither switching nor staying, only that the comparison is unfinished, and a switch would be a posture change that is his.

No lesson is proposed.

**Next:** the #1740 study (OpenAI's Codex Windows sandbox write-up, Microsoft's MXC, then a throwaway spike of the dedicated account, restricted tokens, AppContainer and MXC on the same coder workload, with loopback); it ran on 2026-10-10 and 2026-10-11 and its report is `docs/research/windows-containment-comparison-2026-10-10.md`. The LA caught that the first draft of #1740 covered AppContainer alone, and the ticket description was rewritten the same day.
