### 2026-08-08 — The exam that could not fail, in the ecosystem he cares about most

*Plain summary: the test that decides whether a whole website job succeeded was never itself checked for node projects — so a five-question exam with two blank questions passed, and the build quietly deleted a page he had asked for. Node exams are now checked the same way Python ones already were.*

I went looking for why B9 shipped a pottery site with no individual-piece page and still graded GREEN, and the answer was four lines of code that had been sitting in `shared/fleet/oracle_qa.py` since #821. The seed gate — the thing that decides whether an acceptance oracle is fit to grade a job — opened with `if not rel_path.endswith(".py")`, stamped `collectability: skipped` and `f2p_baseline: not-run`, and returned `seed`. Every non-Python oracle skipped every execution stage. The docstring said so plainly, as intent: *"there is no pytest for a `.mjs` oracle."* That is true and it is not a reason. There is `node --test`, the dispatch driver already grades with it, and node v24 has been on this box the whole time.

The consequence is the part worth keeping. Websites are node jobs, and websites are what the operator says he wants most. So the one ecosystem he named was precisely the one where the highest-authority exam in the system was never proven able to fail. The escaped artifact is 33 lines: five tests, two with empty bodies, one that calls `storeEnquiry` and asserts nothing, one that sets `piece.price = 15.99` and then asserts `piece.price === 15.99`, one that filters an array with `Array.prototype.filter` and checks the result is non-empty. It passes on any tree where its two imports resolve. `oracle-qa.json` recorded `validated: true, findings_total: 0` beside `f2p_baseline: not-run` — the honest field sitting next to the confident one, lending it credibility.

The thing I got wrong first, and the reason I measured before building: I assumed a fail-to-pass baseline would catch this. It does not. I ran the real oracle against a real greenfield skeleton and node reported `tests 1, pass 0, fail 1` — the whole file dies at import resolution and collapses into ONE failing aggregate, which is a clean `all-fail`. The execution stage is blind to this oracle on exactly the tree where it matters. Had I built only what the shape of the Python path suggested, I would have shipped a gate that returned `all-fail` on the artifact that escaped and called it done — a second instrument reporting a measured pass it never measured, which is the defect class I was there to close. What convicts it is a static pass: two empty test bodies, detectable without executing anything. So the change ships both stages, deliberately independent, and the module comment says why neither subsumes the other.

Calibrating the static detector was the real design work, and the brief was explicit that a false REFUSE is much worse than a missed vacuous test, because a false refuse blocks real work. Two shapes convict: an empty body, and a body with no assertion AND no first-party call. I deliberately left the third alone. An assertion-free test that DOES call a first-party symbol is a bare no-raise smoke test — it fails on a skeleton because the call throws, so it genuinely discriminates. This module already knew that: `_exercises_first_party` carries a docstring saying a no-raise first-party call counts, written so "a legitimate smoke oracle passes the floor and is not false-flagged." Hard-refusing that shape statically would have contradicted a rule authored to prevent a false flag. It is caught by measurement instead, wherever the skeleton lets the imports resolve. I also left the tautology shape (`piece.price = 15.99` … `assert.equal(piece.price, 15.99)`) undetected, and that one cost me the most thought: it has a legitimate twin. "Set a field, call the product, assert the field is unchanged" is how you test that a function does not mutate its input. I could not separate the two without a false-positive class I was unwilling to ship, so it stays uncaught and stays written down here.

Then I tested the calibration against evidence rather than against my own confidence. Twenty-one real files — eleven historical job oracles from `state/fleet-runs/` and ten coder-written test files from the B9 project — through the detector. Zero false positives. One flag: the escaped oracle, with exactly its two empty bodies. That run also turned up something I was not looking for. Two oracles (`20260806-094526-bd` and `20260806-171303-bd`) are truncated mid-statement at exactly 6306 bytes, five open braces against four closed, ending on `const habits55 = await get`. Both were seeded as-is, because the node path ran no stage that could look. They now refuse on a `node --check` parse failure, which is the third stage I added and the one I had not planned: node can give a genuine collectability verdict without executing anything, so the flat `skipped` stamp had no excuse either.

The asymmetry the Python path established is preserved exactly: a machinery failure (no node, a timeout, a runner that dies before TAP speaks) is a fail-soft `not-run` with no finding, while a confirmed pre-implementation pass is fail-closed. I checked the single consumer, `_oracle_qa_seed_gate` in `swap_ops.py`, before changing the verdict node can return: it branches only on `verdict == "refuse"`, and nothing in the tree keys off `collectability == "skipped"`. Making node capable of refusing breaks no caller.

What I have not done, and it belongs to items 1 and 2 of #1342 rather than here: `already_satisfied` still trusts a passing oracle without checking whether that pass was measured. This change means a vacuous node oracle no longer reaches it. It does not mean an unmeasured pass has stopped being treated as authority.

**Next:** the `blarai-wt-1342-precheck` limb closes the `already_satisfied` half; once both land, the predicate on #1342 — a B9 run where a vacuous job oracle is refused and `create-piece-detail-page` is dispatched rather than skipped — becomes observable on a single night.
