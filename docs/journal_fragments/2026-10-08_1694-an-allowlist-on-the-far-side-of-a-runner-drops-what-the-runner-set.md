### 2026-10-08 — An environment allowlist downstream of the runner silently drops whatever the runner was careful to set

*Plain summary: the restricted coder's safety settings for git were set correctly by the launcher script and then thrown away one step later by a filter in the Python code that starts the coder's tools; the fix is seven names added to that filter, and the review of it found a second, older instance of the same loss.*

When the coder step moves onto its own restricted account, the launcher script sets seven git variables (no optional index locks, no prompts, no filesystem-monitor daemon, and a trust entry for exactly the coder's worktree). The #1678 builder noticed they might not arrive: `acp_coder.build_env` hands opencode a whitelisted environment, so anything not named never reaches the shell where the coder's git commands run. I confirmed it by reading the function, wrote the fix (the seven names pass through when the parent has them) and four tests: all seven survive, the dictionary for an ordinary run is unchanged when none are set, other `GIT_*` names such as `GIT_DIR` stay dropped, and a toggle that empties the list and shows the survival check can fail.

I took the instruction to keep the ordinary-run environment identical literally, so the change is a passthrough rather than a set: nothing is added unless the parent already holds it. The independent reviewer ran main's and the branch's function side by side under three environments and got identical dictionaries, drove the real ACP spawn call with a stub child to show all seven arrive and `GIT_DIR` does not, and mutated the fix four ways to show each is caught. It also found what my own tests could not: the same whitelist drops the research-docs variables that `fleet-lib.ps1` sets, including the documented emergency stop `BLARAI_RESEARCH_DOCS=0`, so under the live ACP driver that stop cannot fire. That is #1711, deliberately kept out of this change because fixing it alters the ordinary-run environment, which the instruction for this change forbids.

Trade-off: the Python list and the PowerShell list are two hand-kept copies, and nothing asserts they agree. If a third config pair is added on the PowerShell side, the count would pass through without its key and every git command in the coder's shell would fail loudly (reproduced with real git). I left it as a named seam rather than build a count-driven passthrough, because loud failure is the safe direction. The standing gate on a worktree read 5 failed, 26 skipped; a plain worktree of main fails the same five (model files and doc-pointer tests that depend on the primary checkout), so they are environment, not this change; the real-checkout gate on merged main is the figure of record.
