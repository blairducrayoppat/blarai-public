### 2026-10-11 — A coverage check is only as good as its list of what counts as a study

*Plain summary: the research knowledge map was written by hand across four batches, so nothing stopped a new study from never being mapped. I added a deterministic check that every tracked study in docs/research/ is either cited in a map or listed with a real reason, and an independent review then showed my first version had five ways to stay green while wrong.*

I built the check (#1744, audit item #1750) because the map's value depends on completeness, and completeness was only my memory of which files existed. The first version (`9baba7e2`, re-seeded after batch 4 merged in `cfa51f25`) listed what counted as a study by file type, `.md` and `.html`. The reviewer's mutation run showed that was the wrong shape: a `notes.txt`, a `.pdf` or a `.ipynb` dropped out silently, and four guards (the end-of-name boundary, the stale-entry branch for excluded files, the exclusion of the map files themselves, and the no-maps-found error) could be deleted with 17 of 17 tests still passing. The real tree depends on the boundary guard: the folder `windows-containment-comparison-2026-10` shares a prefix with the file `windows-containment-comparison-2026-10-10.md`, so without it citing the file covers the folder.

The rewrite inverts discovery to a deny-list. Every tracked top-level file or folder is a study unless one of a short documented list of exclusions applies (the map files of any extension, the unmapped list, `fixtures/`, `docset-manifest*.json`, and a `<stem>_files` folder only when its saved page `<stem>.htm(l)` exists). The inversion changed the real counts: two `Publication Program ... _files` folders have no saved page in the repo, so they stopped being excluded and are now listed as unmapped. Current result: 68 studies, 55 cited, 13 listed. Discovery uses `git ls-files` (the review's coordinating session decided this): an untracked draft in the primary checkout can never turn the standing gate red, and committing an uncited, unlisted study does, which is intended. Outside a git repository the check scans the filesystem and says so in its output.

Because `tests/security/` is in `SELECTION_ROOTS` of `scripts/run_standing_gate.py`, this test joins the standing gate the moment it merges; there is no separate wiring step, and my earlier note that it would be wired in later was wrong. Citation matching also became stricter and more tolerant in the right places: CommonMark fence rules, HTML comments ignored, a folder is covered only by a citation of an existing child, relative links (`./`, `../research/`, `/docs/research/`), URL-encoded and case-different names accepted. Reasons must be at least 12 characters and not a placeholder. Every test except the real-tree one builds a small synthetic tree with its own `git init` and asserts the specific message, and each guard has a toggle test where the checker with that guard removed passes the violation. The trade-off I did not resolve: a citation inside a 4-space indented block still counts, because nested lists in the maps are indented the same way and treating them as code would produce false reds; that is documented in the script header and pinned by a test.

**Next:** batch 5 maps the 13 listed studies and empties the list; the two `_files` folders need an owner decision to delete or map them.
