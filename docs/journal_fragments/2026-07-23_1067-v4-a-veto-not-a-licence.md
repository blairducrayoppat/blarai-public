### 2026-07-23 — #1067 v4: the fix was not a better proxy, it was making the fallible half a veto

*Plain summary: after three rejected attempts to teach the coordinator's prose guard about negation, the version that held split the question into a part that can grant permission and a part that can only take it away — so a mistake in the unreliable half is always a harmless one.*

I picked up #1067 as a fresh session with the previous session's three rejected designs and a 26-case attack corpus as the floor, plus a recommended v4 design I was explicitly told to treat as a hypothesis rather than a spec. That framing earned its keep: I hunted the recommendation before building it and found it would have shipped a false acceptance.

The recommendation was: excuse a success claim only when the whole text contains exactly one verb-negator and that negator governs the claim's verb, and fix the contraction pattern so `didn't` actually matches. The reasoning behind it is sound and I kept it — adding negators can then only ever push a text toward refusal, so there is no distance an attacker can pad across, which was the specific hole that killed v3's forty-character window. But three things were wrong or missing, and I only found them because I wrote a probe harness and ran the design's *intent* against invented attacks before writing any of it.

The first is the one that mattered. Counting only verb-negators leaves *"it is false that the run did not complete successfully"* at exactly one negator, governing perfectly — so the recommended design accepts it. The sentence asserts the opposite of what its inner negation says, and it says it about a failed run. That is precisely the false-acceptance class that sank v1, v2 and v3, reached through a door none of them had tried: polarity flipped from *outside* the verb phrase, where the government check cannot see it. My fix is to stop using one lexicon for two jobs. Government — the half that *grants* an excuse — stays deliberately narrow: negators that attach to a verb, nothing that attaches to a noun, because "only the migration task ran successfully" is how v1 died. Parity — the half that *vetoes* — uses a deliberately broader lexicon that also counts `false that`, `untrue that`, `denies that`, `inconceivable that` and their family. The asymmetry is the whole design, and it is what I would keep if I kept one sentence: **because government alone can grant the excuse and parity can only remove one, an error in the counting is always a false refusal and never a false acceptance.** The unreliable half is the one that can only tighten. Three rounds of this ticket were spent trying to build a lexical proxy accurate enough to be trusted in both directions; the thing that worked was arranging for one direction not to matter.

The second was quieter. The recommendation said to stop counting in a character window, and said nothing about the government check — which in v3 was *also* a forty-character slice. Removing the window from one and leaving it in the other would have kept a bound to pad past, and slicing has a second problem I confirmed at the interpreter before relying on it: cutting a string mid-word manufactures word boundaries that are not in the text, so a slice landing inside `cannot` produces a bare `not` for the regex to find. Python's `endpos` argument does not do that — it honours the real characters before the search position — so government is now a search with no length bound at all. There is nothing to walk past because there is no window.

The third is not about negation. `"…did not fail to run successfully"` was in the inherited corpus, and no negation logic of any kind can refuse it, because the claim lexicon carried only the past tense `ran successfully` and never matched the sentence at all. A claim the screen cannot see is a hole that no amount of scope reasoning closes, and I had to rediscover it only because I was told — correctly — not to port implementation from the rejected branches.

The trade-off I am buying, and I want it recorded because it will show up as noise in the next shadow window: counting over the whole text refuses accurate prose that carries a second, unrelated negation. *"The card task was not merged. The overall run did not complete successfully."* is true, and this guard drops it. The rejected alternative was to count per sentence or per clause, which keeps that accept and costs a boundary — and every boundary this guard has had, from v1's clause splitter to v3's window, was walked past within a single review round. I would rather pay in dropped-but-true sentences, which cost one cycle's colour, than in a scope line someone can step over, which costs operator trust. The same trade shows up in the government allowlist: anything unlisted between the negator and the claim breaks the excuse, so *"the run did not, after the stall, complete successfully"* is dropped too. Both are asserted as tests rather than left to be discovered, so the price stays visible instead of drifting.

One deliberate scope line: the carve-out lands on run summaries only. The verdict-less annotation door screens success claims outright by contract — it has no verdict to check a claim against — and #1067's measured case is a run summary. Widening the accept surface of the door with less context, on no measured evidence, is the opposite of what three rejected designs just taught.

Fifty false-acceptance bars are now parametrized in the suite: twelve from v1's rejection, six litotes from v2's, eight contraction-and-padding cases promoted out of `xfail(strict=True)`, and twenty-four from this build's own pre-implementation hunt. Guard suite 27 to 101 passing, coordinator evals 85/85, `coord-guard-009` flipped with its history written into its own description rather than overwritten.

**Proposed lesson:** *When a control's correctness rests on a measurement you do not fully trust, do not try to make the measurement better — arrange the control so an error in it can only fail closed. Split the decision into a part that grants permission and a part that withholds it, and put the fallible half in the withholding role. A proxy that can only ever over-refuse is a categorically different object from the same proxy consulted for permission, even when the code is nearly identical.*
