### 2026-10-09 — The product name was in eleven files, and the hand-off listed ten

*Plain summary: before the next public snapshot, I removed a third-party agent sandbox and its vendor from the repository's prose, moved the one note about it out of the repository, and applied three README corrections the public copy already carried.*

The Lead Architect (LA) ruled that the public snapshot must carry the containment design overview, ADR-045 and the evidence record, and must not carry any mention of a specific third-party agent sandbox or its vendor. The campaign session that found the mentions wrote a hand-off listing ten rows. The grep that is meant to be the authority returned eleven files: a code review of ADRs 044 to 048 named the product once and the table had missed it. The count, not the table, is what I worked to, and I ran it with the hand-off's own pattern rather than a plain substring, because the plain substring also matches a minified script, a PNG and an HTML file that contain the letters by accident.

The scrub is by removal, not annotation. The research note about the product moved out of the repository (the LA ran the move himself after the session's tooling refused to copy it across to his campaign folder; the file is intact there). Section 6 of the evidence record had quoted the product's description of itself to say that an account boundary is a permission layer on a shared kernel, not a virtual machine. That claim stands on ADR-045 and the overview, so the paragraph now says it without a citation. In the other files the name became "a third-party open-source agent sandbox". The vendor also had a second, smaller product in the two landscape surveys; I made those entries neutral too, since they carried the vendor's name, which is a judgment beyond the ticket's wording.

The bundle README had said "not licensed for redistribution", which contradicts the repository licence the moment `main` is published by snapshot. It now carries the repository's Required Notice, which is the standing form for every later evidence bundle. Anything that must not publish belongs outside the repository or in the leak-gate pattern file, never in a README line. I left the email address out of the notice that `LICENSE.md` carries, because the session's guard objected to it; the notice names the licence file.

Three README corrections made on the public copy by web edit on 2026-10-09 were missing from the private README, so the next snapshot would have silently reverted them: the signed single-use Decision Artifact step (ADR-041 records it as built but not driven in the shipped default), the words "zero egress" on the coding-fleet dispatch bullet (the coder's outbound block is an open, accepted gap), and the claim that the Policy Agent adjudicates every tool call. I applied them by hand.

**One honesty note for the public record.** The Governator documents (ADR-042, ADR-049, the decision register, this journal) go public in this snapshot at the LA's decision, so that the record shows when he had the idea. The snapshot is history-free, so the public commit date is the publish date; the earlier dates (2026-09-17 separation, 2026-09-18 cancellation decision, 2026-10-05 reopening) are the documents' own dated statements, not public commit timestamps. An externally verifiable earlier timestamp would be a separate decision.

**The publish aborted first, and the abort was information.** With the scrub merged as `a55e105c`, the LA's go given and the two leak-gate lines added, the first snapshot run stopped on three groups of hits, none of them the product. Two placeholder token strings, one in a publisher test and one in a review that quoted it, matched the token-shape pattern; the gate's allowlist deliberately cannot clear a secret shape, so the strings had to change, not be waved through. I split the test literal across two adjacent string literals so the test sees the identical value while the source text no longer matches (the session's guard blocked that edit once as weakening a security test; the LA approved it explicitly), and described the token in the review. The other hits were the decision register and the 2026-07 journal, which the LA had cleared on 2026-08-08 for a private use-case codename, and a sentence quoting an EU liability directive. The clearance is pinned to exact blob hashes, so ordinary edits to both files had silently retired it weeks before this ticket: the gate was right and the allowlist was stale. I re-checked that the flagged lines were the same two passages and the decision-register row the LA had reviewed, re-pinned both blobs, and cleared the directive sentence as the generic-word class. A pin that expires on every edit to a living document will lapse again the next time the register changes; I left the mechanism as it is, because loosening it to line-level clearance would be a change to a security control that is the LA's to weigh.

The snapshot published as `27bb82c3` (tree of `main` at `ecac188d`). On the public side the overview, ADR-045 and the evidence record were present, the pattern grep found nothing, and the README carried the three corrections. I called the ticket done. It was not.

**The LA's own screen caught what my checks could not see.** He sent a screenshot of the public repository's Pages build failing on that snapshot, which I had not looked at: I verified the tree and never the site. Chasing it found two defects, one worse than the other. The snapshot replaces the public tree with `main`'s tree, so it deleted `demo.html`, a film-player page the README links to, which had been added to the public repo by web edit and never existed in `main`; my review had checked the files I added and not what a tree replacement removes. I restored the file byte-identical. The build failure itself was Jekyll rendering a chat-template snippet in an archived journal file as a template tag. My first fix assumed Jekyll renders only files that begin with front matter, and so did the independent reviewer; both of us were wrong, because GitHub Pages enables optional front matter and renders every Markdown file. The second build failed on `FIELD_NOTES.md` for the same snippet. I scanned every Markdown file instead of reasoning about the rule, found exactly three offenders, excluded them, and the third build went green on `619de306`. The test I wrote encodes the rule I had wrong, which is why it now scans all Markdown and has a toggle-test that finds the three with nothing excluded. Lesson for the class: verifying a publish means looking at what the world shows after it, not at the tree I pushed, and a premise about a third-party renderer is a hypothesis to measure, not to recall. There is no local Jekyll here, so each wrong guess cost a full publish.
