### 2026-10-07 — A rule has to arrive before the act it governs, and a hook that cries wolf is a broken hook

*Plain summary: the always-loaded rulebook went from 47,852 to 38,743 bytes by moving seven topic sections, word for word, into files that load only when a session touches their subject, with a hook that delivers them to subagents too; the review found the hook raised false failure alarms on parallel calls, delivered rules one step too late for writes, and (through my own fix) could leak a credential hash to a network path; all three are fixed and proven.*

It started as a small job. #1668's MONITORING gate point had been built on 10-04 and never merged, and by the time I picked it up main had moved 160 commits and `CLAUDE.md` was back to 52 bytes under its 48,000-byte limit, so the point no longer fit. The Lead Architect asked whether moving content to an AGENT.md would help or just move bloat around. It would have moved it: Claude Code does not read AGENT.md, and an `@` import loads at launch at full cost. Then he pointed me at Andrew Stanish's write-up, "Teaching Claude to Code Like Me", and said to execute with that design in mind. My first read of it was a summary from the fetch tool's smaller model, which I said when he asked; the raw page, read in full, carried the two details the summary dropped, and one of them mattered: Andrew's hook ends in `|| true`, so it fails open. Ours had to fail loud.

The design is his three layers. An always-on core. Topic files under `.claude/rules/` with `paths:` frontmatter, loaded when a session reads or edits a matching file. A PreToolUse hook that delivers the same file where native loading does not reach, because he measured 57 subagent writes and zero rule loads, and found shell writes bypassing a Write/Edit trigger 47 minutes after his first fix. I kept the obligations that fire before any file is touched in the core: the journal-entry and ADR rules, Documentation-is-not-evidence, the handoff timing. Each topic file holds one section in the core's own tag register, so the rules-corpus extractor from #1690 splices them back in and every rule keeps its id; a mechanical comparison against main's corpus showed every rule text unchanged except #1668's edits, three scope edits I made to the upkeep rules, and two later corrections. The size fell to 38,743, not the ~30 KB I estimated at the gate: what remains applies to all work, and I did not move it to hit a number. The budget dropped to 40,000 so the room cannot silently refill.

The independent Fable review found a blocking defect I had built and tested past. One state file per agent, written with `os.replace`, raced when one agent issued parallel Reads, which is how every session opens. On Windows the losing replace raises "Access is denied", my catch-all turned it into DOCTRINE DELIVERY FAILED, and the reviewer measured 22 false alarms in 25 two-wide turns. A fail-loud control that fires on its own race is not loud, it is wrong: it tells a working session to go repair something that is not broken. Every test I wrote ran the hook serially, which is exactly why none of them could see it. State is now one marker per agent and rules file; a same-file race yields to an identical winner and is logged, never reported. The new parallel test fails against the old hook, 3 of 3, which I checked before trusting it.

The second finding was structural and I had not seen it at all: PreToolUse context arrives with the tool's result. For a rule whose first application is the write itself, such as a journal fragment, the write goes out uninformed and the rule arrives after it. The reviewer reproduced it live. The fix is a one-time hold: an agent's first Write or Edit on a rules subject is denied, with the rules as the reason, and the re-issued call passes. In a live session the held fragment came back in the entry form it had just been shown. The rejected path was putting the entry form in the always-on core, which would put the bytes straight back where they came from.

The third defect was a security hole, and I introduced it while fixing the reviewer's next finding. To stop the hold firing on files outside the repository I made the hook find a path's checkout by walking up its ancestors and opening each `CLAUDE.md`. The automatic commit security review caught it at once: the hook runs before Claude Code's permission check, so a path like `//host/share/x` in any tool argument, even a word inside a Bash command, would make Windows authenticate to that host and hand over a credential hash. My first fix refused UNC forms one by one; the same review called it incomplete, correctly, because a mapped drive or a junction looks local. Patching the list of bad shapes was the wrong level. The fix that held removes the cause: the list of checkouts comes only from the repository's own git metadata, and a tool-call path is compared as text, never opened or stat'ed. A spy on every filesystem call across nine hostile forms records zero touches, and the reviewer's own audit hook saw none across 44. The rejected path was a longer blocklist, which is the shape security principle 2 forbids.

The memory pass Andrew's "when a rule lives in two places, one of them is already wrong" called for found zero pure duplicates in 141 files and eight conflicts, and the conflicts were the yield. The 09-23 decision to cancel the nightly battery (DEC-14) had only ever landed on an unmerged feature branch, so main's rulebook was still scheduling against 23:00; it is cherry-picked here. The rulebook also said the WinUI app build requires `-r win-x64 --self-contained`, while a 06-30 memory said that writes an exe nothing runs; I built it both ways and the base-folder exe the launcher runs kept its timestamp through the RID build. The doctrine was wrong for three months and the memory was right. Stale memories were updated or deleted, with an archive copy kept beside them.

**Next:** fix-verification by the reviewer, slow git tier and standing gate, merge, then watch the hook log over the next real sessions for how often the hold fires and whether anything other than a first write triggers it.
