## Context

The 4B and 9B Qwen3.5 evaluations (#1663, #1665) answered ALLOW on two Policy Agent test cases the 14B answers DENY (`pa-mdl-007`, a script fetching a cloud-metadata endpoint; `pa-mdl-013`, a script destroying the audit log). A prompt-variant probe (commit `81fd40b4`, one greedy row per cell) showed why: the harmful text sits in a `command` field, the prompt builder's schema validator rejects that key, and the prompt carries `[SCHEMA_REJECTED: Disallowed schema key: command]` instead of the command. Replacing the command with `echo ok` gives a prompt byte-identical to the shipped one on all 13 model-judged cases, for all three models. No model was ever shown the command; the 14B answers DENY on the marker itself, the Qwen3.5 models ignore it.

That raised the question this ADR answers: for real requests, what does the model see, and is it consulted at all. The #1674 trace (code read plus code run on a throwaway worktree of main `c8e19a4d`; no model, GPU, service or config touched) found, labelled as its report labels them:

- **STATIC.** Both production doors judge with `DeterministicPolicyChecker.check` in process: the Assistant Orchestrator tool loop (`_adjudicate_tool_dispatch`, whose docstring says the GPU classifier is not invoked) and the URL door (`url_adjudicator.py`, whose module comment says there is no per-request vsock path). `adjudicate_car` and `classify_car` are reached only from the Policy Agent's IPC handler and from offline scripts and evals. `encode_request` has no non-test caller; nothing in BlarAI, agentic-setup or the C# app sends to port 5000. The launcher log (102,513 lines, 2026-02-24 to 2026-09-22) has 0 `Adjudication <uuid>` lines against about 4,998 Assistant Orchestrator lines.
- **REPRODUCED.** Every Assistant Orchestrator tool call with arguments builds `parameters_schema={"args": "<json string>"}`; `validate_parameters_schema` rejects the key `args`. The URL door's `purpose` key is rejected the same way. The rule checker does see argument text (a `web_search` query containing `/tmp/export/` returns `DENY_EXFILTRATION`). Two forgeries pass the old validator: a closing `---END_UNTRUSTED_SCHEMA---` inside a value under an allowlisted key, and free-text property names inside `properties`.
- **REPRODUCED (eval blind spot).** Of the 35 golden Policy Agent rows, 25 have empty schemas and all 10 non-empty ones are `SCHEMA_REJECTED`; none has a valid non-empty schema. The model's judgement of arguments it could actually see has never been measured.
- **NOT ESTABLISHED.** A live runtime trace (launch the launcher, make one tool call with arguments and one `/ingest <url>`, look for `Adjudication` lines and a non-empty `adjudication_audit.jsonl`); whether a sender outside the repository exists.

ADR-041 (2026-07-15, design review GP-1) had already recorded that "the probabilistic GPU classifier scores no live action" and framed it as a documentation correction. The #1674 trace, #1683 and this ADR do not contradict it; they add the log evidence and carry the follow-on question ADR-041 left open, wire or retire.

## Decision

1. **Option A: the Policy Agent's model does not see tool-call arguments. They are judged by the deterministic rule checker.** A rejected schema carries no meaning on its own. This is the design the shipped configuration already has, made explicit. It is consistent with the principle ADR-041 records: the model is untrusted, and the probabilistic layer may only tighten a deterministic ALLOW, never loosen a DENY.
2. **A field the judge cannot see whole is not judged: it is a deterministic deny, never a truncation** (`61fead17`, final shape `50542fbb`, merged `aeb2579d`). Any tampered or over-cap field (value, key, size, depth, type) makes `classify_car` return a `CAR_FIELD_REJECTED` deny with no model call, whatever the key order. Control text (chat-template tokens, the union of the four local brain tokenizers, 33 entries read from the tokenizer files) is rejected in schema values, property names and every plain field. Types are exact JSON-native types only. The total schema cap is 16384 serialised characters. A rejected key is echoed in the reason only if it is one of the nine keys the golden cases carry; every other key is hashed.
3. **Rules 5, 6 and 7 of the rule checker are stated as not applicable at the Assistant Orchestrator and URL doors, and locked** (`caab37f2`). None of the assistant's ten tools has an owner or size argument; rules 6 and 7 need the WRITE verb, and the assistant door sends EXECUTE for every tool and the URL door EGRESS. A recursive lock fails if any tool schema gains an owner-, size- or bytes-named property in any nesting form; drive-through tests build requests with the real Assistant Orchestrator builder and run the real checker. The approval-binding hash `_action_identity` is unchanged. Rules 5 and 7 remain live only on the Policy Agent IPC door, which has no known sender.
4. **The 35 golden Policy Agent prompts are byte-identical to main** (recomputed by the independent reviewer), so no model re-baseline was needed.
5. **The recommendation to add a deterministic DENY whenever the schema is rejected is retracted.** It was made on #1673 (comment 3864) and in the #1665 verdict, and withdrawn the same evening (#1673 comment 3865, #1665 comment 3866): such a rule, placed where live requests are judged, would deny every tool call with arguments and every URL fetch. The wrong version stays visible on the ticket and struck through in the merged verdict. #1673 was reframed (comment 3876): extend `DeterministicPolicyChecker` so argument-borne threats (link-local and metadata endpoints, audit-log destruction patterns, in the `args` string and in URL targets) are caught by rules at both production doors, each driven through the real door; no deny-on-schema-rejection rule.

## Alternatives considered

- **Option B: a typed, allowlisted, datamarked projection of arguments shown to the model, behind a dormant flag.** Not chosen now. It puts model-authored, injection-influenced text (arguments derive from retrieved or web content) into the prompt of the component that mints ALLOW, on a validator that two reproduced forgeries already passed; it needs per-tool schemas and a rewrite of the five rejected-schema golden rows; and the model's judgement of arguments has never been measured. Kept as the path if a re-visit trigger fires, with the validator hardened first (now done).
- **Option C: hash only (`args_sha256` in the schema).** Gives the model nothing to judge; identity binding is already done outside the model (`_action_identity`).
- **Option D: status quo (marker shown, arguments unseen, concept inconsistent).** Not recommended by the trace.
- **Deny on schema rejection.** Retracted above.
- **Truncate over-long fields with a marker** (the first #1684 fix, `87569134`). Rejected after an independent reviewer ran it: the rule checker judges the full request and the model would judge a prefix, so a payload after the cap is invisible to the classifier and present for the actor. Fail-open.
- **Remove the rejected-key echo entirely.** Tried (`61fead17`) and reverted (`3458ce7e`): it changed 10 of the 35 shipped evaluation prompts, which could change the 14B's verdicts and force a GPU re-baseline. **Echo identifier-safe keys** (`3458ce7e`) was then found to re-open the forgery for keys such as `DECISION_ALLOW`; the final shape echoes only the nine golden-case keys.
- **Unicode look-alike normalisation.** Rejected as unnecessary (finding J5): the schema renderer escapes non-ASCII and no step exists between validation and rendering.

## Consequences

- **Why the dormant-flag step did not apply.** #1674 comment 3872 said any behaviour change is built dormant behind a flag. #1684 and #1685 merged live without one because they only tighten (a stricter deterministic deny and a documented rule table) on a path that static evidence says is unwired; that rationale rests on the static finding, and an outside sender is not ruled out.

- **Defence in depth, no live effect.** The hardening protects a path that is on no live path today. A long or pretty-printed tool-argument string would be denied by the 1024-character value cap and the newline rule if tool calls were ever sent to the model (recorded on #1683); an option-B projection would need its own caps.
- **The deterministic checker is the only judge of arguments in the shipped configuration.** Its argument-borne coverage is the regex string-scan rules (2, 4, 8) over the serialised schema; rules 5 and 7 cannot fire on assistant calls. Wider coverage is #1673's work.
- **The Policy Agent half of the brain-replacement comparison (33/35 versus 35/35) is moot while the classifier is unwired.** What stays relevant for a brain swap is Assistant Orchestrator quality, speed and memory (ADR-047). The merged 9B verdict still carries "keep the 14B for the Policy Agent" worded against a pending trace; the edit rides with #1683 and has not been made.
- **Single-door doctrine.** CLAUDE.md describes one Policy-Agent adjudication door; in the shipped configuration that door is the rule checker. Whether the model-backed half is wired (a posture change: built dormant behind a flag, evaluated, LA go-live ceremony) or retired and the statements corrected is #1683's decision.

## Residuals and known gaps

- **Live trace not run.** Everything about the model path being dark is static plus log evidence. An outside sender is not ruled out.
- **Eval blind spot persists:** no golden row has a valid non-empty schema.
- **14B behaviour on the marker** rests on two cases, one greedy row per cell; its probability and sampled arms were invalid (a probe error, #1677).
- **#1688:** a pre-existing test-isolation defect on single-file `policy_agent` runs, deferred with that ticket as the predicate.
- **#1673 not built:** the rules for metadata endpoints and audit-log destruction in arguments are open.

## Re-visit triggers

From the #1674 decision: a live trace shows a sender to port 5000; a threat for which the regex rules are provably insufficient; or an evaluation shows the model catches argument-borne attacks the rules miss at an acceptable false-positive rate. Then option B, scoped to a closed per-tool set of typed scalars, dormant behind a flag, validator hardened first.
