# Landing-Card Template (tracked) — handoff briefs, v2

Discipline SSOT: `CLAUDE.md` `<context_handoff>` + `<event_time_banking>` (LA-ratified
2026-07-28, #1144; evidence: `docs/governance/claude_code_context_audit_2026-07-28.html`).
This file is the fill-in structure. `scripts/verify_handoff_brief.py` machine-enforces it
for briefs dated **2026-07-29 or later**: `template: landing-card-v1` frontmatter required,
**≤150 lines / ≤8 KB**, required sections present, no pasted ops block, anchors verified.
Briefs dated earlier verify under legacy rules (anchors only) — history is not rewritten.

**A landing card hands over OBJECTIVES, DELTAS, and POINTERS — never a rebuilt world.**
Every durable fact is ALREADY in its home (board, journal, LESSONS, FIELD_NOTES, registers)
because it was banked at event time per `<event_time_banking>`. The card carries only what
has no durable home: machine state and the thread position. If writing one takes more than
minutes, or teaches you something while writing it, banking failed upstream — fix that, not
the card.

**THE GATE (load-bearing, unchanged in authority):** a card never authorizes execution. The
successor grounds on disk → verifies anchors → presents its gate → **WAITS for
User-Operator confirmation**. A NEW engagement gets the FULL `CLAUDE.md` comprehension gate
(role & authority / context / goal / task + plan / scope / inherited constraints /
risks + decision points / assumptions & ambiguities / open questions — all nine, own
words, built from the reads). A CONTINUATION of an already-gated program gets the **delta-gate**
(LA-ratified 2026-07-28): ≤10 lines — what changed, what I will do next, what I need from
you — still presented and confirmed before substantive action. Doing-the-work authorization
is NEVER gate-skip authorization; never frame a card as "execute end to end" (the
2026-07-05 anti-pattern).

**RETRACTIONS & DEAD ENDS are pointer-form.** The correction or dead end was banked where
it happened, when it happened (superseded banner on the record, ticket comment at
abandonment). The card lists `banked at #N (comment, YYYY-MM-DD)`. Content living in the
card is a banking failure. "None" is a valid answer; omission is not.

**AUTHORING:** run `python scripts/author_landing_card.py --topic <slug>` — it emits the
frontmatter, a pre-filled anchors block, and the ENTIRE stamped Machine-state section; you
write Objective, Deltas, Next step, Pointers. Author at a work boundary while sharp (plan
the landing from ~60% context use; land by ~75–80%) — never after degradation.

**FILE:** `docs/handoffs/<topic>-landing-<YYYYMMDD>.md`. **Date the filename** — the
directory is gitignored, so a same-name overwrite is unrecoverable. Surface the path in
chat at handoff (a successor grounding via git alone will not find a gitignored file).
*(Historical correction, kept because commit `8dbb2164`'s message cannot be rewritten: the
dated-filename rule stands on the gitignored-overwrite reason above; that commit's
"undated names collide and the older brief silently wins" justification was never
observed.)*

**ANCHORS (machine-checked):** every card carries a filled ```anchors block. Rows are
pipe-delimited `<type> | <value> | <label> [| <derivation>]`; types: `sha` (ancestor of
main), `path` (exists), `count` (4th field = the shell command that re-derives it — RUN it
before pasting; use a `| wc -l` pipeline so a zero count still exits 0), `ticket` (`#NNN`).
A leftover `<placeholder>` FAILS. The successor runs the verifier at grounding step 2.

2. **Verify anchors:** `python scripts/verify_handoff_brief.py docs/handoffs/<this-card>.md`

   `docs/governance/session-ops-surface.md` — cite, never paste.
