# Disposition — #1541, Gap A (bind the approval to the action, re-derived before execute)

**Review run 2026-09-17, pre-merge, by an agent that did not write the code.** Target `d134c859`;
fixes in `9cbdfa5a`. The reviewer's merge read: *"Do not block on correctness. Block on the record."*
That distinction is the substance of this disposition.

**The code is sound.** Nothing false-positives, every error path denies, the hash is deterministic
and argument-sensitive, `session_id` is correctly excluded so the Hello N=3 lease holds, the regex
holds against nine adversarial shapes, and no bypass exists — removing the reset produces false
*refusals*, never an execution.

**What must not be claimed** is that Gap A is closed and verified. Three findings say why.

## What the reviewer attacked and could not break

- **No false positives.** The identity derivation is fully deterministic — no uuid, timestamp or
  dict-ordering leakage; `session_id` correctly excluded via `VOLATILE_FIELDS`. The real approved
  path executes. No legitimate turn refuses.
- **Fail-closed throughout**, driven through the real connection handler: empty identity refuses,
  drifting identity refuses.
- **No identity smuggling** — nine adversarial shapes, `fullmatch` correct, no raw text reached the
  context or the operator-facing description.
- **No bypass.** No path executes a second dispatch under a first approval; removing the reset
  yields false refusals, never an execution.
- **No regression.** 7359 passed at the reviewed content; the 2 failures and 3 skips are exactly the
  documented worktree artifact and the non-elevated symlink class.
