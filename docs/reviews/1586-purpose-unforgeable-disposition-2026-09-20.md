# Disposition — #1586 (settle `purpose` before anything goes to the LA)

**The ticket asked one question and attached a hazard to it.** The question: does an
egress request carry unforgeable-enough provenance to key the consent model on? The
hazard: `purpose` is a caller-supplied string, and if anything the model influences
can set it to the ingest value, that request gets *paste-is-consent* semantics for an
arbitrary host — the difference between "the operator pasted this" and "the model said
the operator did".

**The answer is YES, and it is proved rather than argued.** So the second half of the
ticket's Done applies: the single adjudicator is built, and the test that could not be
written while two factories competed for one slot now exists.

**#977 was never a governance question**, and that is the finding with the longest
reach. The runbook recorded it as an LA posture call about which adjudicator should
win. Both policies are correct for their own request, the discriminator was already in
the CAR, and the "conflict" was a wiring accident wearing a policy costume.

## Verification

**Mutation, on the shipped source, selection named** (`test_url_adjudicator_both_postures.py`

**Two rounds, and the second one mattered more.** The first battery reported 7/7 and
the record was written on it. The review then defeated the central lock three ways,
found the no-host fix applied to one branch of two, and found two surviving mutants
the battery had not thought of. A mutation score is a statement about the mutants
you wrote.

## The honest note

The ticket's own framing said settling this might show that no LA decision was needed,
and that is how it turned out — a question had been sitting in a runbook for months
labelled as his, when the information needed to answer it was in the request the whole
time. The part worth carrying is not the fix. It is that "which policy should win?"
was the wrong question, and it stayed unasked-and-unanswered precisely because it
sounded like a governance call rather than a bug.
