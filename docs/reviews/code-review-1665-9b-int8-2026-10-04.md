## Blocking

### F1 BLOCKING - `hf_publish.py` passes a dash-leading `--path-in-repo` straight to `hf upload` as an option
`scripts/hf_publish.py:203-209` (`_validate_target`) checks for leading `/`, `\`, `..` segments and a trailing `/`,
but not for a leading `-`. Using the `=` spelling, argparse accepts it, preflight passes, and the value lands in the
path-in-repo POSITION of the hf argv, where the hf CLI parses it as a flag.
Cost when it fires: `hf upload REPO DIR --delete=*` uploads to the repo root and deletes every remote file matching
`*` from the PUBLIC dataset, which cannot be undone from here.
Reproduced (fake `HF_EXE` recording argv):
```
python scripts/hf_publish.py upload --dir clean --config c1 "--path-in-repo=--delete=*" --message m   -> exit 0
recorded argv: ["upload","blairducrayoppat/openvino-arc140v-lunarlake","clean","--delete=*","--repo-type","dataset","--commit-message","m"]
"--path-in-repo=--revision=x"  -> also exit 0, forwarded as "--revision=x"
```
That `hf upload --delete` really removes files remotely is a hypothesis (real CLI not run, per constraints); delivering
the flag to `hf.exe` is reproduced. `test_upload_rejects_traversal_path` covers only `../x`.

### F2 BLOCKING (for any write-up claim) - MTP-on vs MTP-off quality outputs are NOT byte-identical for the 9B; the compare instrument checks only one run
`scripts/analyse_phase1_quality.py:214` `compare()` checks only `*-pinned-V0-r1`, so `compare_9b_on_vs_off.json` reports
`identical: true` for both suites. Across all pinned io logs, the prompts are identical but the outputs differ:
```
agentic-pinned-V3-r1  38/38 calls  prompts_same True  outs_same False  out_diff 2
(all other pinned tags: 0 differing outputs; PA random r2/r3: 13 calls, identical)
```
The calls that differ are index 10 (prompt_sha e17bb6940bb89bad, the injection "budget ceiling" answer: the wording diverges mid-reply) and
index 26 (prompt_sha 8c6273ae3d197743: "only accepts" vs "only supports"). Reproduced by pairing every
`q9b_on/*_io.jsonl` with its `q9b_off` twin on `prompt_sha`/`out_sha`.
The same thing happens in the banked 4B Phase 1 data: `agentic-pinned-V3-r1` has 1 of 40 outputs differing with identical prompts. So the
merged verdict line "its answers were byte-for-byte identical with and without it in every check"
(`docs/research/qwen35-4b-mtp-phase1-verdict-2026-10-04.md:31`) is contradicted by Phase 1's own banked io logs.
The parenthetical scopes it to the 5-prompt speed check, but "in every check" does not hold.
Cost: a "MTP is lossless" claim to the LA and on the public card that the banked data refutes. The brief's expectation
("byte-identical via the io logs for pinned runs") is false as stated. Speed-campaign identity
(`mtp_off_vs_on_identity_9b`, 5 short prompts) does hold in A1-A5.

`build_phase1_dataset.py:45-54` `sanitise_report` handles `actual` only when it is a string. `oracle_quality` cases carry
`actual` as a dict with a `detail` string, which survives the builder. `hf_publish.py:70-78` then flags it.
```

  -> 7x 9b-on-all-random-r1_report.json + 7x 9b-off-...: generated-text field 'detail'   (14 problems)
```

turns off the generated-text check for every `detail` key in the tree. The pre-merge tests never ran the builder's output
through the preflight. Incidence: 100% of real datasets (2 of 2).
