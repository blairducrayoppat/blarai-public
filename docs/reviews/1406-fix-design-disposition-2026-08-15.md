# Disposition — adversarial review of the #1406 fix design, 2026-08-15

**Why this pass happened.** #1406 is the Lead Architect's own hands finding what the gates
passed, and it is the THIRD instance of one class (#1116, #1126, now this). A fix authored by
the same session that mis-scoped the class twice before does not get to certify itself, so the
design was written up and attacked on disk by two independent reviewers before any of it shipped.

**It was worth doing.** The routing decision survived — intercept on the two question states,
never on a parked plan — but three defects in my own design did not, and one of them would have
made the remedy worse than the defect. All three are fixed in `41b6a4e3`, the same commit as the
fix itself; none was ticketed for later.

The reviewers also convicted the *structural control* I had specified. Its first-draft oracle —
"every instruction line must mention `/dispatch`" — would have passed the single worst string on
the surface, because *"Reply with the number (e.g. `2`), or `/dispatch reject` to cancel"* does
mention it, in the other half of the sentence. A control that certifies the exact string causing
the bug is the #1241 instrument-honesty class wearing a test file. The shipped oracle is
clause-shaped and drives each literal through the real parser.

## The correction this record exists to carry

The first version of this disposition said the routing design "survived" review. It did not. Two blockers were found on the second pass, and **both were invisible to the first** because that pass reasoned about the code and this one ran it. The `/external` gap needed every parser executed against one string; the clarifying-notice gap needed a real question parked and the printed literal fed back through the parser.

The uncomfortable one is the second blocker. This change ships a control whose whole thesis is *drive the printed literal through the machine that must accept it* — and the same change printed a literal the machine refuses, in the neighbouring slot, composed at runtime where the control cannot see it. Author-is-not-verifier is not a formality here; it is the only reason this is a corrected record rather than a fourth incident in production.

## What this pass did NOT cover

It attacked a design and the code that came out of it. It did not run the app. The strings were
read, not seen on screen — and the whole reason this ticket exists is that a reading has now been
wrong twice about what the operator would actually experience. The live check against his exact
flow is a separate step, recorded on #1406.

It also cannot see an instruction the operator infers from a layout rather than from a sentence,
nor one composed by the model at runtime. The structural control reads shipped string constants;
that is its whole reach, and it is stated in its own module docstring rather than left to be
discovered.
