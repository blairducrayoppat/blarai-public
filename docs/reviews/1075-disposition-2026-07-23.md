# Disposition — #1075 (the dedup guard marks a task done on clean EXIT, not on DELIVERY)

**Change under review:** two branches, both `feat/1075-deliver-not-exit`.

- **agentic-setup** — `scripts/run-fleet.ps1`, `scripts/new-agent-task.ps1`
- **BlarAI** — `shared/fleet/swap_driver.py`, three test files, one journal fragment

**Reviewer:** independent, not the author. **Verdict:** **MERGE**, reached over four passes —
pass 1 returned one blocker (F2), one required fix (F1) and three record-and-go (F3–F5); pass 2
returned one required fix (N1 — the F4 fix reintroduced F4's own class at the budget boundary),
two record corrections (N4/N5) and three record-and-go (N2/N3 + the F5 blocklist limit); pass 3
returned O1 and O2; pass 4 returned MERGE with two text corrections (P1/P2), one record-and-go
(P3) and one nit, all folded in below.

**The most important row in this record is O1, and it is not a defect row — it is a control.**
F4, N1 and O1 are three instances of ONE class: *the skip line asserting a reason it cannot
know*. It claimed "delivered" for a spent budget, then "budget spent" for a task that delivered
on its last permitted dispatch, then "never dispatched" for a task that was. Each time I fixed
the branch. `CLAUDE.md` requires a third instance to ship a **structural control in the same
change**, and it was right: the branch was never the bug. `done.txt` records the fact and not
the reason, and no ordering of predicates recovers information nobody wrote down. Every writer
now records its reason through one function and the skip **looks it up** — there is no branch
left to be wrong, and the crash window degrades to an honest "not recorded" instead of a
confident wrong answer. The structural form is smaller than the point fix it replaced.

Every row below was reproduced by execution before being reported. Every FIXED row names the
commit that carries the fix and the toggle-off that proves the lock sees the defect.

## Notes on the two DEFERRED rows

**`merged-owner-repairs-still-refused`** is not a residual of my fix; it is a pre-existing
consequence the fix makes legible. `_run_static_pregate_fix_cycle` only ever targets a
just-merged task, so `done.txt` has refused it since the guard existed — meaning it has never
once reached a coder, and every historical "fix cycle did not re-merge" line in the trail was
this guard rather than a coder failing. **Provenance, corrected:** I found this while building,
raised it in my hand-back, and the *integrating session* — not any independent review — made
the scope call and supplied the **measurement**-defect framing. An earlier draft of this record
credited the review with both. It raised neither, and inflating apparent review coverage in a
record that feeds a portfolio is exactly the kind of error the record exists to prevent.
That framing is right whoever said it: this is a measurement defect, not a missing capability.
Layout and exec-smoke are only partially
affected (`_OWNER_STATUS_RANK[PARKED] = 0` prefers a parked owner, and after this change the
parked-owner case works), so how much of the trail is uninterpretable versus merely suspect
differs per gate. Closing it changes what a re-dispatch MEANS and touches the queue schema —
a decision, not a defect fix. Ticketed with the observable predicate above.

**`live-dispatch-never-exercised-repair`** is deferred because it cannot be closed by any
amount of test-writing. The locks drive the real `run-fleet.ps1` under real `pwsh` through the
real `real_run_task`, but the coder is stood in for. A stub proves the TRANSPORT — does the
dispatch reach `new-agent-task.ps1` — and can never prove the SEMANTICS: whether a real model,
given the rewritten package-contract prompt, actually produces `app/card_entry.py` with
`app/__init__.py` beside it. Only a live run answers that.

My first draft of this row named "the first battery run" as the predicate and `verify_disposition.py`
refused it — correctly. That phrase reads like a reason and decides nothing: no later session
can check it, and no queue contains it. It is now **#1087**, with a predicate a successor can
actually grep for, and the ticket states that a run containing no non-delivering task is NOT a
pass — it means the path went unexercised and the ticket stays open. Worth recording that the
gate caught this, because the row was written by the same person who wrote the section below
about deferrals needing observable predicates.

## Honest limits recorded rather than closed

- The hermeticity guard is **inspect-before-spawn, not structural impossibility**. The fleet
  root is an absolute real path; short of a filesystem sandbox nothing makes the write
  physically impossible. A future test calling `swap_ops.real_run_task` directly, bypassing
  the rig, escapes both seams. Recorded on the ticket (c.2492) so "guarded" is never read as
  "impossible".
- `-MaxTaskDispatches` counts dispatches; the per-dispatch retry loop can spawn the coder up
  to `$maxAttempts` times within one ledgered dispatch, so the real ceiling is the product.
  Both are finite; the parameter name is accurate for what it counts, and the comment now says
  so explicitly rather than leaving a reader to assume otherwise.
- A pre-fix toggle-off run created a live `state/fleet-runs/R1075` in the operator's real fleet
  tree before the hermeticity guard existed. Removed; verification and its limit are on the
  ticket. Evidence kept.
