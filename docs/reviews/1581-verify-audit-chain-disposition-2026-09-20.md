# Disposition — #1581 (verify the audit record without rotating a key)

**Eleven findings from an independent adversarial review, every one reproduced by the
reviewer before reporting. Three were blockers. The review also confirmed the change's
central claim and sharpened its mechanism.**

**The finding in one line: building a command to check the audit record turned up THREE
copies of the key-verification ladder, all written by the same sprint, all diverged at the
error path — and the third copy raised `TypeError` on every invocation of the ceremony the
runbook tells the operator to run.**

## Verification

`tests/security/` (not hardware/winui/slow): **1390 passed**, plus the 2 known ADR-013
worktree doc-pointer artifacts, which pass on the primary checkout — confirmed by running
them there on merged main earlier today.

`test_verify_audit_chain.py` **37 passed**; `test_audit_key_rotation.py` **51 passed**
(48 before, +3 for the ceremony that nothing had ever driven).

**Fifteen mutations run in total**, each removing one fix and confirming its lock fails.
**Six did not fire on the first attempt** and are recorded above as findings against my own
locks: three I caught myself before the review (findings in the journal fragment), three the
review caught (4, 6, 8), plus the `rotate_signing_key` guard, which is redundant with
`_rotate_active_segment`'s on every current path and is now held structurally by
`test_every_write_method_guards_read_only_at_its_own_top` rather than by any single call
path.

**Live verification**, which no test here can produce: run against the real TPM-signed
`ingest_audit.jsonl` on this machine, the command reports VERIFIED, 33 records, 2026-06-11
to 2026-07-13, exit 0 — and the file's mtime and byte size are identical afterwards, with
`services/policy_agent/data/` still absent although the command resolved that path and
found no chain there.

## The honest note

I built the wrong lock four times in this change, and each time the mutation is what said
so. Twice the test verified a test double that reimplemented the thing under test. Once it
passed because an early return made the guard unreachable on that path. Once it asserted
only a negative, so a mutation that made every answer negative satisfied it. A green test is
a claim about the code; only removing the code tells you whether the claim was about the
code or about the test.
