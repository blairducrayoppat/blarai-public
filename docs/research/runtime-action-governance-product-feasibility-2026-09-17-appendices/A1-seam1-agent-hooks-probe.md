## Outcome, in plain language

A third-party governor can plug into Claude Code's PreToolUse (pre-tool-use) hook on this machine today, see every tool call the agent is about to make (tool name, full arguments, session, working directory, permission mode), and veto it — and the veto holds even when the operator launches the agent in "bypass all permissions" mode. The cost is one Python process per tool call, about 86 ms median here, invisible next to the 8–23 s a whole prompt takes. But the seam is cooperative: the same agent honours `--safe-mode`, which silently skips the hook; a hook that crashes (exits 1) is treated as "no opinion" and the command runs (fail-open); and the hook sees one command string, not what the command does (a network fetch inside `python -c` passed as an allowed `Bash` call). GitHub Copilot CLI 1.0.3 ships an equivalent `preToolUse` hook (JSON files under `.github/hooks/` or `~/.copilot/hooks/`) but this account's Copilot policy denies CLI use, so it could not be exercised. Codex CLI is not installed; its documented hooks have the same shape and are explicitly described by OpenAI as "not a complete enforcement boundary". Microsoft Defender's AI agent runtime protection (Preview, docs dated 2026-09-16) consumes exactly these three hook points from Claude Code, Codex CLI and Copilot CLI, and requires Defender for Endpoint Plan 2 with the device onboarded — neither is the case here (Defender Antivirus is not running; Bitdefender is the active AV).

### What escapes a PreToolUse hook (docs AND observation)
1. Command semantics. One `Bash` event carries one string; the child processes it spawns, the files those read, the sockets they open are invisible (run c1: an HTTPS fetch passed as plain text). Claude Code's own `if` field can match Bash sub-commands syntactically (`$()`, `&&`, leading assignments — docs), but that is still text matching.
2. Anything that does not route through the hook: work done inside an MCP server after its tool is invoked (the event is the invocation, not the server's I/O); actions on the model-provider side; tools whose names the matcher does not cover (a matcher is an allow-list of names to watch, so an unmatched new tool is unwatched).
3. Operator switches (MEASURED): `--safe-mode` ran the denied command with the hook never invoked (run e1). `--setting-sources` selects which files load; a hook in an unselected file does not exist for that session. Documented but not run: `--bare` ("skip hooks"), `disableAllHooks: true`. Only hooks delivered as managed settings survive `--safe-mode` and `disableAllHooks` (docs), and the managed file is editable by a local administrator (docs; this user is an administrator).
4. Governor failure (MEASURED): a hook that exits 1 is treated as "no decision" and the command runs (run d2). Only exit 2 or a JSON `deny` blocks. A governor process that crashes, or a Python that is missing, fails open by design of the seam. Timeouts: documented default 600 s, then non-blocking — not measured.
5. Content the payload does not carry: no prompt text, no prior turns, no tool result (those are other events: `UserPromptSubmit`, `PostToolUse`), so a PreToolUse-only governor judges each call without conversational context unless it reads `transcript_path` itself.

- Config schema (zod): `{ "version": 1, "hooks": { sessionStart | sessionEnd | userPromptSubmitted | preToolUse | postToolUse | errorOccurred | agentStop | subagentStop: [ { "type": "command", "bash"?: str, "powershell"?: str, "command"?: str (alias for both), "cwd"?, "env"?, "timeoutSec"? (alias "timeout") } ] } }`. Unknown events are ignored with a debug line. Eight events in 1.0.3; the current docs list fourteen (adds `userPromptTransformed`, `postToolUseFailure`, `preCompact`, `permissionRequest`, `subagentStart`, `notification`) — the installed build predates the docs.
- Discovery: every `**/*.json` under `<git root or cwd>/.github/hooks/` and under `<config dir>/hooks/` (`~/.copilot/hooks/`), plus plugin `hooks.json` / `hooks/hooks.json`; lists are concatenated.
- Execution: on Windows `powershell` entries run `pwsh.exe -nop -nol -c <cmd>`, `bash` entries run `bash.exe --norc --noprofile -c <cmd>`; when both are given, Windows picks `powershell`. Input JSON is written to the child's stdin; stdout is parsed as JSON (unparseable → undefined); default timeout 30 s.
- preToolUse input: `{sessionId, timestamp, cwd, toolName, toolArgs}` where `toolArgs` is the raw `function.arguments` string. Output honoured at the call site: `permissionDecision === "deny"` → tool result replaced by `Denied by preToolUse hook: <reason>` with `resultType: "denied"`; `modifiedArgs` replaces the arguments. (`allow`/`ask` are in the SDK type and docs; they are not consumed at this site in 1.0.3 and I did not trace the permission-prompt path.)
- Error policy in 1.0.3: the hook loop is wrapped in `try { … } catch (c) { o = c; log.error("preToolUse hook execution failed: …") }` and the function then returns only the denial map — a hook that exits non-zero, times out, or crashes does not deny; the call proceeds (fail-open). The current docs state instead: exit 2 and other non-zero exits are fail-closed for preToolUse, timeouts fail-open. Artefact and prose disagree; the artefact is the older build. A governor targeting Copilot must therefore assume fail-open on any version it has not read.
- `changelog.json` entries (version-tagged in the file): "preToolUse hooks can deny tool execution and modify arguments", "Load personal hooks from ~/.copilot/hooks in addition to repo-level .github/hooks", "Support 'command' field as cross-platform alias for bash/powershell in hook configs", "Add agentStop and subagentStop hooks".
- No audit log path is documented on either GitHub page fetched; a third-party blog claims `.github/hooks/logs/audit.jsonl` — not verified, not present in 1.0.3 strings.

Docs read: `https://docs.github.com/en/copilot/reference/hooks-reference` and `https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-hooks` — neither shows a page date or minimum CLI version. Windows user-level path per docs: `%USERPROFILE%\.copilot\hooks\`. Hooks are also accepted inline in `.github/copilot/settings.json` / `~/.copilot/settings.json` (docs; the `~/.copilot/settings.json` here is `{}`).
